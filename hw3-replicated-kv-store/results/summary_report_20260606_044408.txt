--------------------------------------------------------------------------------
KEY FINDINGS
--------------------------------------------------------------------------------

1. CONSISTENCY vs AVAILABILITY TRADE-OFF:
   - Eventual consistency provides fast writes but allows stale reads
   - Strong consistency prevents stale reads but increases write latency

2. NETWORK DELAY IMPACT:
   - Higher network delays increase convergence time in eventual consistency
   - Higher network delays increase PUT latency in strong consistency
   - Stale read probability increases with network delay

3. FAILURE HANDLING:
   - Eventual consistency continues accepting writes during partial failures
   - Strong consistency may reject writes if majority is unavailable
   - Failed replicas miss updates and need catch-up mechanisms

4. CONFLICT RESOLUTION:
   - Last-Write-Wins (LWW) provides deterministic conflict resolution
   - Concurrent updates are resolved automatically based on timestamps
   - LWW can silently discard data (the losing write)

--------------------------------------------------------------------------------
CONCLUSION
--------------------------------------------------------------------------------

This exercise demonstrated the fundamental trade-offs in distributed systems:

- There is no 'one size fits all' consistency model
- The choice depends on application requirements:
  * Social media: Eventual consistency (can tolerate temporary staleness)
  * Banking: Strong consistency (cannot tolerate inconsistencies)
  * Gaming: Low latency (may accept eventual consistency for performance)

- The CAP theorem forces a choice between consistency and availability
  during network partitions

- Real-world systems often use tunable consistency (per-operation choice)
