KEY FINDINGS
================================================================================

1. CONSISTENCY vs AVAILABILITY (CAP Theorem):
   - Eventual consistency (AP): Fast writes, allows stale reads
   - Strong consistency (CP): No stale reads, slower writes
   - Choice depends on application requirements

2. NETWORK DELAY IMPACT:
   - Eventual: Convergence time increases linearly with delay
   - Strong: PUT latency increases linearly with delay
   - Stale reads increase with delay in eventual consistency

3. FAILURE HANDLING:
   - Eventual: Continues operating, failed nodes miss updates
   - Strong: May reject writes if majority unavailable
   - Both need catch-up mechanisms for recovering nodes

4. CONFLICT RESOLUTION:
   - LWW is simple and deterministic
   - Silently discards losing writes
   - Not suitable for all data types

================================================================================
RECOMMENDATIONS
================================================================================

Choose consistency model based on requirements:

  EVENTUAL CONSISTENCY (AP) when:
    - Low latency is critical
    - Temporary staleness is acceptable
    - High availability is required
    Examples: Social media feeds, DNS, CDN, caching

  STRONG CONSISTENCY (CP) when:
    - Data correctness is critical
    - Stale reads are unacceptable
    - Can tolerate higher latency
    Examples: Banking, inventory, authentication
